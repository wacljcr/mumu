# QQ图文同发（com.wacljcr.qqmixtxtimg）

手机 QQ 也能图文一条发

选好照片（或表情）点发送的那一刻，输入框里打的字会自动并进同一条消息 —— 和电脑 QQ 一样的体验，不用再发完图/表情再补一句文字。

⚠️ 重要：本机显示限制（必读）

自己手机上刚发出的那条消息，可能看不到文字（只看到图或表情）。这是 QQ 9.3.70 NT 架构的本地回显机制限制，不是插件没生效。

  • 聊天气泡内容由 QQ 自己的 Swift 管线在「点击发送」瞬间一次性构建，插件层拿不到那个渲染入口，无法让本机气泡即时刷新。
  • 必须返回聊天列表、再进入会话，文字才会显示出来；或者直接看对方手机 / 电脑端，都是即时可见的。
  • 文字确实已经随消息一起发出去了。屏幕顶部闪一下「✓ 文字已随表情发出」的提示，就是给你即时确认的，不用等。

> 一句话总结：发出去对方一定能看到文字；自己手机上想看，退出去再进来就行。

怎么用（就一步）

1. 在 QQ 聊天输入框里正常打字

2. 然后任选一种方式发送：

  • 点 「+」→ 相册，选照片（单张多张都行）发送
  • 打开表情面板，点收藏的表情包发送
  • 点 QQ 自带的大表情（黄色大图那种）发送

3. 发出去的那条消息就是图片/表情 + 你刚打的文字

4. 发送成功后输入框自动清空，屏幕顶部会闪一下「✓ 文字已随表情发出」提示

> 没打字、只发纯图片/纯表情时，不会弹任何提示，也不会把之前的字带出去。

功能一览

  • 图文合并发送 — 相册选图发送时，自动把输入框文字并入同一条消息，文字作为消息正文、图片作为配图，接收方看到的就是电脑端那种「图片 + 文字」
  • 收藏表情包带文字 — 打字后去表情面板点收藏的表情包发送，文字自动并进同一条消息
  • 自带大表情带文字 — 打字后点 QQ 自带的黄色大表情发送，文字同样自动并入
  • 发送提示 — 文字并入成功时屏幕顶部轻提示「✓ 文字已随表情发出」，1.8 秒自动消失，不打断操作；没打字只发表情时绝不误弹
  • 多图支持 — 一次选多张照片，文字同样只并进这条消息
  • 发送后自动清空 — 文字已经并入消息，输入框立刻清空，紧接着打下一句就行
  • 不干扰正常使用 — 纯文字、纯表情、转发、收藏等所有其他操作原样不动；正常发完文字消息后再单发表情，不会把之前的字带出去
  • 实时取样 + 短窗口 — 发送瞬间主线程实时采样输入框（10 秒窗口）优先，退化为最近输入快照（20 秒窗口），彻底替代原先 5 分钟长缓存，杜绝旧文字残留误注入
  • 运行时自适应校准 — 自动学习 QQ 消息元素类型枚举，QQ 小版本更新导致枚举变化也能自愈
  • QQ 自带工厂构造 — 复用 QQ 自己的消息元素构造器，不手搓协议结构，稳定性与原生发送一致
  • 设置开关 — 设置 → QQ图文同发，总开关一键停用，改完立即生效不用重启 QQ

兼容与说明

  • iOS 14 及以上 · rootless 越狱（Dopamine / Relaxin / RootHide）
  • 运行依赖 ElleKit / Substrate（deb 已自动带上依赖）
  • 实测适配 QQ NT 架构（QQ 9.3.70）；QQ 大版本更新如失效会跟进
  • 只改 QQ 客户端发送行为，不碰账号、不上传任何数据
  • 仅限个人学习使用

更新记录

1.1.13 · 2026-10-30

修掉"没打字发表情也弹提示"的误报 + 修复实验版递归闪退。

  • 修复误弹提示 — 用户反馈"只要发表情就出现『文字随表情包发出』，没输入文字也有提示"。根因是文字快照长缓存残留：删字/清空后没失效，残留被当"刚打的字"注入并弹提示。现已改为发送瞬间实时采样输入框 + 收紧时间窗口（实时 10 秒 + 快照 20 秒，替代原先 5 分钟长缓存），空输入绝不再弹提示、也不会把旧文字误带进表情消息
  • 修复递归闪退 — 撤回上一测试版为做"本机即时显示"而对内核事件分发点（onAddSendMsg:）的全量 hook：该点命中 QQ 多播分发器，触发无限递归打穿栈保护（SIGBUS 闪退）。现已移除，运行稳定
  • 防双发 / 防误带 — 发送入口、消息记录、NT 落库三层注入均带结构校验与"已注入"守卫，QQ 内部对消息模型变更时自动退避，不影响正常收发
  • 本机显示限制已坐实 — 经对落库层 / 内核通知总线 / Swift 渲染管线多轮逆向，确认 QQ 9.3.70 聊天气泡由 Swift 管线在点击发送瞬间一次性构建，插件层无法干预。维持"退出重进会话后本机可见、对方/电脑端即时可见"现状，发送轻提示可即时确认
  • 版本 1.1.11 → 1.1.13

1.1.11 · 2026-10-30

稳定性加固 + 本地回显机制攻坚收官。

  • 修复本地回显实验引入的崩溃隐患 — 中间实验版本曾把未包装的消息元素直接塞进消息记录，导致对元素调方法时无法识别而闪退；现已在所有注入路径统一套上 QQ 自己的元素包装层，并增加类名守卫：遇到非预期结构自动跳过注入、原样透传，绝不硬来
  • 发送链路多层防御 — 发送入口、消息记录两条路径的注入均带结构校验，QQ 内部对消息模型的包装变更时自动退避，不影响正常收发
  • 本地回显结论 — 经对消息落库层、内核通知总线、Swift 渲染管线的多轮逆向确认：QQ 9.3.70 聊天气泡内容由 Swift 内部管线在点击发送瞬间一次性构建，插件层无法干预。因此本机发送瞬间看不到文字属 QQ NT 架构限制，对方手机、电脑端、退出重进会话后均正常显示，发送轻提示可即时确认文字已发出

1.1.5 · 2026-10-30

表情包模式全面打通 + 稳定性修复。

  • 修复表情包模式闪退 — 根治了构造消息元素的引用计数失衡问题（对象被提前释放后 autorelease 池二次释放导致崩溃），v1.1.1–1.1.2 的闪退彻底解决
  • QQ 自带大表情也能带文字 — 输入框打字后点自带黄色大表情发送，文字自动并进同一条消息（此前只有收藏表情包支持）
  • 新增发送轻提示 — 文字并入成功时屏幕顶部闪现「✓ 文字已随表情发出」，自动消失；自己手机上刚发出的消息因 QQ 本地回显不显示文字时，提示可确认文字已发出
  • 防误发保护 — 正常发完文字消息后（输入框已清空）再单发表情，不会把之前的文字带出去
  • 发送窗口收紧 — 文字快照有效窗口从 10 分钟收紧到 5 分钟，更精准
